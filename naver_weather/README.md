# naver_weather — 네이버 날씨 실시간 수집·검증

> [playwright-e2e](../README.md) 저장소의 스위트 하나입니다. 대상: 네이버 날씨 (서울 · 강원 · 경기)

Python + Playwright + pytest 로 네이버 날씨에서 **세 지역의 현재 날씨와 시간별 강수량을
실시간으로 수집하고, 그 값이 맞는지까지 검증**합니다.

크롤링 데모가 아닙니다. **긁어온 값이 쓸 수 있는 값인지 판정하는 것**이 이 저장소의 목적입니다.

```
53 tests — 53 passed   (약 9초, Chromium headless)
```

---

## 수집 경로 — 화면 두 개를 건너갑니다

```
검색(search.naver.com)              상세(weather.naver.com)
┌──────────────────────┐          ┌──────────────────────┐
│ 현재 기온 · 상태     │  지역코드 │ 시간별 기온          │
│ 체감 · 습도 · 풍속   │ ────────▶│ 시간별 강수확률      │
│ 강수확률(오전/오후)  │          │ 시간별 강수량(mm)    │
└──────────────────────┘          └──────────────────────┘
```

**강수량(mm)은 검색 카드에 없습니다.** 상세 화면에만 있어서 한 화면에서 다 읽은 척하지 않고
링크를 따라 넘어갑니다. 이때 주소를 코드에 적어 두지 않고 **카드가 실제로 들고 있는 지역 코드**를
읽어서 이동합니다 — 그래야 링크가 엉뚱한 지역을 가리키는 날 그 사실이 잡힙니다.

| 지역 | 검색어 | 화면이 답하는 이름 | 관측 지점 |
|---|---|---|---|
| 서울 | `서울 날씨` | 서울특별시 | 중구 을지로1가 |
| 강원 | `강원도 날씨` | **강원특별자치도** | 인제군 상남면 |
| 경기 | `경기도 날씨` | 경기도 | 양평군 개군면 |

## 무엇을 검증하는가

검증을 세 갈래로 나눴습니다. **실패했을 때 어느 쪽인지 바로 갈리게** 하기 위해서입니다.

| 마커 | 파일 | 묻는 것 |
|---|---|---|
| `contract` | `test_contract.py` | 화면 구조가 우리와 맺은 계약대로인가 |
| `range` | `test_ranges.py` | 값이 물리적으로 가능한 범위인가 |
| `consistency` | `test_consistency.py` | 두 화면·두 값의 **관계**가 성립하는가 |

```bash
pytest -m consistency      # 관계 검증만
pytest -m "not range"      # 범위 검사 빼고
```

### 관계 검증이 핵심입니다

값 하나만 보면 통과하는데 관계를 보면 깨지는 것들이 있습니다.

- **카드가 가리킨 지점과 상세 화면의 지점이 같은가** — 링크가 어긋나면 사용자는 남의 동네 날씨를 봅니다
- **실황과 시간별 예보가 3° 넘게 벌어지지 않는가** — 같은 지점 같은 시각인데 크게 다르면 둘 중 하나가 틀렸습니다
- **비가 오는데 강수확률이 0%인 시간이 없는가** — 논리 모순 검사. 오늘은 비가 안 와서 빈 목록을 확인하고 지나갑니다.
  **비 오는 날에만 의미가 생기는 검사를 미리 넣어 둡니다**
- **세 지역이 서로 다른 지점을 보는가** — 지역 코드가 겹치면 이름만 다르고 값은 같은 곳이 됩니다.
  지역별로 하나씩 도는 테스트로는 절대 잡히지 않아서, 세 지역을 한 번에 보는 검증을 따로 뒀습니다
- **수집 시각이 하나의 스냅샷으로 묶여 있는가** — 세 지역을 다른 시각에 긁으면 비교 자체가 성립하지 않습니다

## 만들면서 잡은 것

**자정 칸만 라벨 형식이 다릅니다.** 시간별 표의 0시 열은 `0시` 가 아니라 **`내일`** 로 옵니다.
`…시` 만 골라내는 파서는 **하루에 한 칸씩 조용히 빠뜨립니다.**

처음 실행에서 세 지역 모두 `시간이 건너뛴 지점: 23시 → 1시` 로 잡혔습니다.
값이 틀린 게 아니라 없어진 것이라, 시간 연속성 검사가 없었다면 리포트가 멀쩡해 보였을 겁니다.

```python
DAY_MARKERS = {"내일": 1, "모레": 2}   # 자정 칸은 시각 대신 날짜 라벨이 붙는다
```

## 실행

**저장소 루트에서 실행합니다.** (스위트 디렉터리가 아니라)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium

pytest                              # 전체 검증
pytest --headed                     # 브라우저를 띄워서 확인
python -m naver_weather.collector   # 수집만 — out/snapshot.json 생성
python -m naver_weather.report      # 수집 + HTML 리포트 생성
```

실패하면 `test-results/` 에 스크린샷·영상·trace 가 남습니다.

## 구조

```
.
├─ conftest.py       세션당 1회 수집 · 지역 파라미터 픽스처
├─ collector.py      두 화면을 건너가며 지역 하나를 수집
├─ report.py         수집 결과 → HTML 리포트
├─ pages/            Page Object — 셀렉터는 전부 이 안에만
│   ├─ base_page.py            문자열 → 숫자 파싱 한 곳
│   ├─ search_weather_page.py  검색 카드(현재 관측값)
│   └─ today_page.py           상세(시간별 강수량)
├─ data/regions.py   대상 지역 + 값의 허용 범위
└─ tests/            contract · range · consistency
```

**수집은 세션당 한 번만 합니다.** 테스트마다 다시 긁으면 같은 대상을 수십 번 두드리게 되고,
테스트 A 와 B 가 서로 다른 시각의 값을 보게 되어 실패가 제품 문제인지 시차 문제인지 구분되지 않습니다.

## 설계에서 신경 쓴 것

**① 기대값을 검색어에서 만들지 않습니다.**
`강원도` 로 검색해도 화면은 `강원특별자치도` 를 말해야 합니다(2023년 개편).
검색어를 그대로 기대값으로 쓰면 **제품이 옛 행정구역명을 노출해도 통과**합니다.

**② 허용 범위에 근거가 있습니다.**
기온 -35~45°는 국내 관측 극값(41.0° 2018 홍천 / -32.6° 1981 양평)에 여유를 둔 값입니다.
1시간 강수량 상한 200mm 도 국내 기록(약 145mm) 기준입니다.
'숫자면 통과'로 두면 습도 자리에서 풍속을 읽고도 통과합니다.

**③ '값이 없다'와 '읽지 못했다'를 구분합니다.**
표의 적설 `-` 는 정상이라 `None` 으로 두지만, 파싱 실패는 `ParseError` 로 올립니다.
둘을 같이 `None` 으로 두면 **비가 안 오는 것과 강수량을 못 읽은 것이 같은 값**이 됩니다.

**④ 위치가 아니라 라벨로 읽습니다.**
`dt.term` 을 라벨로 찾아 바로 뒤 `dd` 를 읽습니다. n번째로 읽으면 항목이 하나 추가되는 순간
**테스트는 통과하는데 다른 값을 보고 있는** 상태가 됩니다.

**⑤ 표를 시간 단위로 뒤집어 들고 다닙니다.**
화면은 `행=항목 / 열=시간` 인데 검증은 시간 단위가 자연스럽습니다.
표 모양 그대로 두면 테스트마다 인덱스 계산을 다시 하게 됩니다.

**⑥ 아이콘이 아니라 대체 텍스트를 읽습니다.**
날씨 상태를 아이콘 이미지로 판정하면 그림이 틀려도 알 수 없고,
스크린리더 사용자가 받는 값과도 달라집니다.

## 알려진 제약

- **대상이 외부 공개 사이트**라 화면이 바뀌면 영향을 받습니다. `contract` 마커의 테스트들이
  그 경우를 가장 먼저 잡도록 분리해 뒀습니다.
- 지역은 3곳 고정입니다. `data/regions.py` 에 한 줄 추가하면 검증 전체가 그 지역까지 자동으로 돕니다.
- 브라우저는 Chromium 만 실행합니다.
- 강수량이 0인 날에는 강수 관련 검증이 **빈 목록을 확인하는 형태**로만 돕니다.
  비 오는 날 한 번 더 돌려 봐야 실제 값에 대한 확인이 끝납니다.
